# Записи журнала, которые ждут релиза

Одна запись - один файл. На релизе они собираются в секцию `CHANGELOG.md` и
`CHANGELOG.ru.md`, а отсюда исчезают.

Так сделано ради одной вещи: две ветки больше не пишут в одно и то же место
одних и тех же двух файлов. Раньше каждая добавляла строку под `## [Unreleased]`
в конец своей категории, git не мог отличить одну от другой, и всё, кроме первой
влитой ветки, разводилось руками - на двух языках, и заново после каждого мержа.

## Как добавить

Положи сюда файл `<что-сделал>.md`:

```markdown
### Fixed

#### en
Fixed the order form refusing a service assembled from several charts.

#### ru
Исправили отказ формы заказа на сервисе, собранном из нескольких чартов.
```

Категория - одна из шести: `Added`, `Changed`, `Deprecated`, `Removed`, `Fixed`,
`Security`.

Оба языка обязательны. Это не формальность: файлы журнала должны держать одни и
те же записи в одном порядке, и пока обе половины лежат в одном файле, нарушить
это нельзя.

Переносы строк внутри записи - твоё удобство, смысла в них нет. Запись это один
абзац, а переносить его по ширине будет сборщик, так что твой файл не может
испортить вид готового журнала.

Имя файла ни на что не влияет, кроме порядка внутри категории: он по алфавиту.

## Как писать саму запись

Правила формы - в `.claude/rules/changelog.md`, и они сильнее общих: одно
предложение, глагол впереди, без прошлого, с названием места в портале. Там же
пары «было / стало» на наших же ошибках - прочитай их перед тем, как писать свою.

## Что посмотреть и как выпустить

```bash
make changelog                  # показать, что накопилось, ничего не трогая
make changelog VERSION=0.16.0   # собрать в оба файла и убрать отсюда
```

Секции `## [Unreleased]` в файлах журнала больше нет: несобранные изменения
живут здесь. Побочный эффект: страница «О портале» на сборке между релизами их
не показывает, только выпущенные секции.
