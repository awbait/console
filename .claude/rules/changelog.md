# Журнал изменений: разбор на наших ошибках

Метод целиком лежит в скилле `changelog`. Здесь - то, что специфично для этого
репозитория, и живые примеры того, как записи уже портились. Их проще применять,
чем правила: перед тем как написать запись, прочитай пары «было / стало».

## Кто читает

Клиент платформы: разработчик, который заказывает сервисы через портал. Он не
знает наших внутренних понятий, не читал issue и не видел прошлых версий
интерфейса. Из записи он должен понять три вещи: что изменилось, где это в
портале, что ему с этим делать.

## Пары «было / стало»

**Обрубок без места.** Короткое предложение, которое не отвечает на «где».

| Было | Стало |
| --- | --- |
| Владелец сервиса узнаёт, что версию согласовали или отклонили. | Команда, которая публикует сервис, получает уведомление о решении по своей версии: согласована или отклонена. В отказе сразу виден комментарий согласующего. |
| Портал сообщает о собственном обновлении. | О собственном обновлении портал тоже присылает уведомление. По нажатию открывается журнал изменений на разделе с этой версией. |
| Кнопка «Прочитать все» снимает счётчик разом. | Уведомление можно отметить прочитанным, не открывая: наведите на него и нажмите галочку. Кнопка «Прочитать все» снимает счётчик разом. |

**Ссылка на то, чего читатель не видел.**

| Было | Стало |
| --- | --- |
| Полосы в каталоге больше нет. | Раньше об этом было сообщение на странице каталога, теперь его нет. |

**Внутреннее слово вместо обычного.** Название элемента интерфейса вводится один
раз, дальше пишем действие обычными словами.

| Было | Стало |
| --- | --- |
| Портал пишет об этом в колокольчик. | Портал присылает уведомление. |
| В колокольчик приходит сообщение, когда сервис развернулся. | Уведомление приходит, когда заказанный сервис развернулся. |

**Красивость вместо факта.** Если фразу надо расшифровывать, она не работает.

| Было | Стало |
| --- | --- |
| Страница продолжала выглядеть свежей. | На странице оставались старые данные. |
| Ожидание выглядит как контент, который вот-вот появится. | Пока данные загружаются, портал показывает их заготовку вместо надписи «Loading». |
| Меню сохраняет единую геометрию при сворачивании. | Свёрнутое меню не сдвигает значки, они остаются на той же линии. |
| Страница согласования публикаций перестала уезжать. | На странице согласования публикаций заголовок остаётся на месте, прокручиваются только списки под ним. |

**Механизм вместо экрана.** Первое предложение говорит то, что видно на
странице, а не то, как это устроено внутри.

| Было | Стало |
| --- | --- |
| Портал читает видимость поля из сработавшей ветки схемы чарта. | Форма заказа скрывает поля, которые не подходят к уже выбранным значениям. |
| Какие поля скрывать, решает сам чарт. | (убрать: читателю нечего с этим делать) |

**Пересказ починки вместо одной строки.** Одно исправление - одна запись, и
чаще всего одно предложение. Как оно устроено внутри, что теперь означает статус
и что доделает миграция при обновлении - это разбор для issue, а не для
читателя.

| Было | Стало |
| --- | --- |
| Изменение и удаление уже развёрнутого сервиса портал оформляет как MR. Если такой MR закрыли, не влив, заказ навсегда застревал в статусе «Отклонён»: сам сервис работал, а изменить, обновить или удалить его через портал было уже нельзя. Теперь заказ возвращается в тот статус, в котором был до изменения. (и рядом ещё две записи: про смысл статуса и про уже застрявшие заказы) | Заказ больше не застревает навсегда в «Отклонён», когда MR на изменение или удаление сервиса закрыли без влития. |

**Домысел про читателя вместо факта.** Предложение «что было» описывает
поведение портала или кластера. Что делали люди, мы не проверяли.

| Было | Стало |
| --- | --- |
| Раньше поле «Домен» заполняли и для TCP, а заказ кластер не принимал. | Раньше поле «Домен» показывалось при любом протоколе, а заполненный домен не давал гейтвею развернуться. |

**Два языка в одном предложении.** Английский файл целиком английский.

| Было | Стало |
| --- | --- |
| A point on TCP or UDP no longer has the "Домен" field. | A point on TCP or UDP no longer asks for a domain. |

**Длинное предложение с придаточными.** Разрезать, но не потерять «где» и «что
делать».

| Было | Стало |
| --- | --- |
| Значение, из-за которого заказ не приняли, объясняется теми же словами, которыми поле подсказывало при заполнении: «Не короче 3 символов.» вместо «length must be >= 3, but got 2», а пропущенное значение показывается на самом поле. | Форма заказа объясняет отказ теми же словами, что и подсказка у поля. Вместо «length must be >= 3, but got 2» портал пишет «Не короче 3 символов», а поле, которое вы пропустили, подсвечивается само. |

## В этом репозитории

- Два файла в одной правке, одинаковые по структуре: `CHANGELOG.md` (английский)
  и `CHANGELOG.ru.md` (русский). Число записей в каждой секции должно совпадать.
- Проверить это можно так:

  ```bash
  counts() { awk '/^## \[/{if(n)print n; n=0} /^- /{n++} END{if(n)print n}' "$1"; }
  diff <(counts CHANGELOG.md) <(counts CHANGELOG.ru.md)
  ```

- `CHANGELOG.md` пишется по-английски целиком, включая названия страниц, кнопок
  и полей, хотя интерфейс у нас русский. Точная строка из интерфейса стоит в
  `CHANGELOG.ru.md`, и за ней читатель идёт туда. В секциях 0.7.0-0.8.1 ещё
  лежит старая конвенция с русскими названиями в кавычках.
- Длинное тире запрещено и здесь (общий запрет из `CLAUDE.md`).
- Описания уже выпущенных GitHub Releases собраны из этих файлов. Если правишь
  выпущенную секцию, обнови и релиз:

  ```bash
  awk -v tag='## [' -v v="0.4.0" 'index($0, tag v "]")==1{f=1;next} index($0,tag)==1{f=0} index($0,"[")==1{f=0} f' CHANGELOG.md > notes.md
  gh release edit v0.4.0 --notes-file notes.md
  ```

## Кто нашёл проблему

Когда о проблеме сообщила команда со стороны, запись заканчивается подписью:
жирная метка и название команды, без ссылки на PR и без номера issue.

```markdown
- Управлять сервисом может только команда-владелец. Чарты, которые портал нашёл
  сам, оставались открыты на управление любому участнику любой команды, и такой
  сервис можно было забрать себе. **Нашли:** DBA
```

В английском файле метка та же по смыслу: `**Reported by:** DBA`.

- Подпись идёт последней и только у записи о самой находке. Если одно
  исправление разложено на несколько записей, подпись ставится на ту, которую
  человек и увидел.
- Отдельной строкой подпись сделать нельзя: парсер (`internal/changelog/parser.go`)
  склеивает перенос внутри пункта в один абзац. Отбивает именно жирная метка.
- Предложением («Нашла команда DBA») не пишем: это половина записи по длине, а
  сути в ней нет.
- Имена людей в журнал не попадают, только команда. Человека называют разбор в
  issue и трейлер `Reported-by:` в коммите.

## Перед коммитом

Перечитай каждую новую запись и ответь за читателя: что изменилось, где это
увидеть, что с этим делать. Если на любой из вопросов ответа нет - запись не
готова.
