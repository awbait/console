# Тексты для пользователя пишет codex

Любой текст, который увидит пользователь продукта, генерирует не Claude, а
codex (OpenAI Codex CLI, стоит на машине: `codex --version`). Claude собирает
факты, формулирует задание, принимает результат и кладёт его на место. Сам
текст Claude не сочиняет и не переписывает.

## Что считается текстом для пользователя

- Записи журнала изменений: `changelog.d/*.md`, правки в `CHANGELOG.md` и
  `CHANGELOG.ru.md`, описания GitHub Release.
- Строки интерфейса в `web/src`: подписи полей и кнопок, ошибки валидации,
  подсказки, описания, пустые состояния, тултипы, заголовки, тексты
  диалогов, `web/src/pages/configText.ts`, `fieldErrors.ts`.
- Документация, которую портал показывает в разделе «Документация»:
  `web/public/docs-content/**`.
- Тексты ошибок бэкенда, которые доходят до экрана (ответы API, которые
  интерфейс показывает как есть).
- NOTES.txt чартов: чарты живут в отдельном репозитории со своими правилами,
  но текст там тоже для пользователя, и порядок тот же.

## Что Claude пишет сам

Комментарии в коде, сообщения коммитов, тела PR и issue, комментарии к ним,
документация для разработчиков в `docs/`, правила и скиллы в `.claude/`,
логи, метрики, тексты тестов. Это читают разработчики, а не пользователи.

## Порядок

**1. Бриф.** Файл в scratchpad сессии, не в репозитории. В нём:

- что за продукт и кто читатель (пользователь портала, не разработчик);
- факты: что изменилось, где это видно, что нужно сделать пользователю;
- какие файлы с правилами текста codex должен прочитать до ответа:
  `.claude/rules/ux-copy.md` для интерфейса, `.claude/skills/changelog/SKILL.md`
  и `changelog.d/README.md` для журнала;
- запреты этого репозитория, явно: без длинного тире «—», без точек с
  запятой, без имён компонентов, пропсов, функций и внутренних сущностей;
- языки и формат ответа: «только содержимое файла, без пояснений и без
  обрамления в ```». Для нескольких строк одной правки: один бриф со списком,
  ответ списком «ключ: текст».

Готовый ответ codex должен ложиться в файл без правок, поэтому формат
задаётся в брифе, а не чинится после.

**2. Запуск.** Без интерактива, только чтение, без сохранения сессии:

```bash
codex exec -s read-only --ephemeral -C D:\work\idp --color never -o <scratch>/out.md - < <scratch>/brief.md
```

Ответ приходит в `out.md`, ход работы в stdout (его можно отправить в лог
и не читать). Обычный прогон занимает до минуты, таймаут команде давать
5 минут. Одна запись журнала стоит около 20 тысяч токенов codex.

**3. Приёмка.** Claude читает `out.md` и проверяет формально: оба языка на
месте, категория верная, нет «—», нет «;», нет имён из кода, факты не
искажены. Подходит - кладёт как есть. Не подходит - отправляет обратно новым
запуском: тот же бриф плюс «предыдущий вариант: ...» и «что не так: ...»
по пунктам. Своими словами Claude не исправляет. Механику править можно:
имя файла, типографские кавычки, переносы строк, отступы.

**4. Codex недоступен** (команды нет, ошибка входа, нет сети): сказать об
этом пользователю и остановиться на этом тексте. Не писать его самому молча.
Если пользователь скажет писать самому, текст пометить в PR как написанный
без codex.

## Почему

Тексты для пользователя - продуктовая работа, и у неё один автор: так тон,
формулировки и словарь одинаковы во всём продукте, а не зависят от того, какая
сессия правила файл. Claude в этой цепочке отвечает за факты и за проверку,
codex - за слова.
