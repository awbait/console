# Стенд, скрипты и сборка: находки

Пункты про PowerShell относятся к Windows PowerShell 5.1 - это то, что стоит на
машинах, где поднимается стенд. Инструкция по стенду - в `docs/development.md` и
`deployments/kind/README.md`.

## PowerShell 5.1

- **`2>$null` у нативной команды - не тихая проверка, а способ уронить скрипт.**
  PowerShell заворачивает каждую строку stderr в `NativeCommandError`, и при
  `$ErrorActionPreference = 'Stop'` это завершает выполнение. То есть
  `docker manifest inspect`, отвечающий «not found», убивает скрипт вместо того,
  чтобы вернуть код возврата. Такие проверки делаются через обёртку, которая на
  время вызова возвращает preference в `Continue` (`Invoke-Quiet` в наших
  transfer-скриптах).
- **`$name:$ver` - это не интерполяция, а обращение к диску.** Двоеточие после
  имени переменной парсится как префикс PSDrive. Пиши `${name}:$ver`.
- **JSON в аргументе нативной команды теряет кавычки.** Квотирование нативных
  аргументов в 5.1 срезает внутренние двойные кавычки, и `curl.exe -d '{...}'`
  доезжает пустым. Тело пишется во временный файл и передаётся как `-d "@file"`.
- **Только ASCII в `.ps1`.** Файл без BOM читается как ANSI, и длинное тире
  ломает парсер. (В проекте длинное тире запрещено и так, но здесь это ещё и
  синтаксическая ошибка.)
- **Разбор JSON - `ConvertFrom-Json`, а не вызов python.** На машине, где стенд
  поднимают, python может не быть.
- **Что остановило скрипт, печатается одним предложением через `trap`.** Причина
  почти всегда во внешней среде (не заполнена карта чартов, у токена нет
  доступа), и оператору нужна эта фраза, а не позиция строки. `finally`
  разворачивается раньше `trap`, так что уборка не страдает.

## Контейнеры и сеть стенда

- **`docker compose up -d` возвращается, когда контейнер создан, а не когда
  сервис отвечает.** Порт опубликован сразу, соединение принимается и тут же
  рвётся, и клиент падает с голым `EOF`. Ждём настоящего ответа от сервиса
  (у Keycloak - discovery-документ) и говорим, какой лог смотреть, если ответа
  так и нет.
- **`start_period` у healthcheck обязателен там, где первая инициализация
  долгая.** `initdb` Postgres на Docker Desktop под Windows занимает до двух с
  половиной минут, а без `start_period` контейнер объявляется unhealthy через
  30-60 секунд, и зависимые сервисы не стартуют.
- **Сразу после старта Docker Desktop `docker info` уже отвечает, а auth-эндпоинт
  движка ещё нет.** Несколько секунд `docker login` возвращает 500 (`API route
  .../auth`). Ожидание демона по `docker info` от этого не спасает, поэтому сам
  `docker login` ретраится (transfer-скрипты, Connect-Harbor).
- **`host.docker.internal` - имя для контейнеров, не для хоста.** С хоста оно
  резолвится не на всех бэкендах Docker Desktop. Хостовые вызовы (health-пробы,
  REST, push) идут на `127.0.0.1` и опубликованный порт; `host.docker.internal`
  остаётся только там, где адрес должен совпасть с внешним URL сервиса (у нас -
  OCI token realm у Harbor).
- **Публичные реестры образов бывают недоступны.** В стенде мы перепиновываем
  единственный образ с `public.ecr.aws` на Docker Hub перед применением
  манифеста.
- **Realm Keycloak импортируется один раз.** Файл импорта не применяется к уже
  существующему realm, поэтому второй адрес (доступ по LAN, другой порт)
  регистрируется через admin API. Отказ регистрации - предупреждение, а не
  остановка: он влияет только на вход.
- **У dev-стенда свои значения секретов, и они лежат в раннере.** Портал
  отказывается стартовать с дефолтным `SESSION_SECRET`, а браузер выкидывает
  Secure-куку на обычном HTTP по LAN-адресу, поэтому раннер выставляет и
  фиксированный локальный секрет, и `COOKIE_SECURE=false`.
- **Скрипт сброса стенда должен уметь удалять то, что сам не создавал.**
  `reset-state.ps1` пропускал Application без finalizer'а и оставлял предыдущий
  стенд работать при пустой базе портала. Теперь он проставляет finalizer перед
  удалением.

## Сборка и репозиторий

- **Байтовое сравнение плюс `go:embed` требуют закреплённых переводов строк.**
  Миграции и `atlas.sum` вшиваются в бинарь, а контрольная сумма считается по
  байтам: на машине с `core.autocrlf=true` старт падает с «checksum mismatch».
  Такие файлы пинуются в `.gitattributes` как `text eol=lf`. То же самое для
  сгенерированного `.env.example`, который сравнивается с генератором побайтово.
- **Правило `.gitignore`, начинающееся со слэша, привязано к корню.**
  Инструмент, который пишет рабочий каталог рядом с местом запуска, обойдёт
  такое правило. Если каталог может появиться где угодно, правило пишется без
  якоря.
- **Артефакты сборки удаляются сразу после проверки.** `go build` в рабочем
  каталоге оставляет бинарь, который потом уезжает в коммит.
