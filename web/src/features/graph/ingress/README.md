# Ingress Gateway в конструкторе графа

Открыть: `playground.html?graph=ingress` или кнопка **Ingress Gateway**
в конструкторе, открытом со страницы топологии.

Это локальный прототип адаптера для `console-charts/ingress-gateway` версии
**11.0.0**. `values.schema.json` и `view.schema.json` рядом с кодом скопированы
из этого чарта. При обновлении версии нужно обновить оба файла вместе и
проверить пример через `helm template`. Подключение к реальным заказам пока
не добавлено.

## Маппинг

| Элемент графа | Источник |
| --- | --- |
| Namespace Gateway | Namespace установки Helm, отдельно от values |
| Gateway | `/gateways`, ключ `name` |
| Строка Gateway | `listeners`, ключ `name` |
| backendRef | `/xroutes/*/rules/*/backendRefs`, ключ `(namespace, name, port)` |
| Namespace backendRef | `namespace` ссылки либо Namespace установки Helm |
| Связь | Каждая комбинация parentRefs и backendRefs в правиле xroute |
| Форма связи | Элемент `/xroutes`, форма `views.routes` и enum-правила вкладки routes |

Пустые области и ещё не подключённые backendRefs хранятся в состоянии редактора
в браузере. Они не добавляют вымышленных полей в Helm values и не создают
Namespace или Service в кластере. Один граф представляет одну установку чарта:
все её Gateway находятся в Namespace установки. В другие области можно помещать
ссылки на сервисы через поле namespace.

Соединение выхода Gateway или его слушателя со входом backendRef открывает
новый xroute с заполненными parentRefs и backendRefs. Клик по подписи открывает
тот же SchemaForm, который используется в обычной форме маршрута: matches,
filters, timeouts, веса, sessionAffinity и другие поля остаются доступны.
Один xroute может отображаться несколькими линиями, но редактируется целиком
одной записью. Маршрут без backendRefs, например redirect, показан петлёй на
Gateway; все маршруты также доступны кнопками под холстом.

Изменение адреса карточки backendRef обновляет все совпадающие ссылки, сохраняя
параметры каждой ссылки, включая её вес. Настройки конкретного правила меняются
через форму xroute. Переименование Gateway обновляет явные parentRefs.

Вкладка **Обычная форма** использует `views.order`; **Values YAML** позволяет
посмотреть и применить полный документ. Данные сохраняются в localStorage
`console-graph-ingress-v1`. Сброс примера запрашивает подтверждение.

## Что это проверяет для общего конструктора

Текущий declarative-профиль рассчитан на отдельные массивы узлов и связей.
Ingress использует вложенные массивы и связи «многие ко многим», поэтому
маппинг здесь задан адаптером в `model.ts`, а не набором плоских коллекций
в GraphDesigner. Общий GraphView и обычный движок форм переиспользуются.
Следующее расширение декларативного формата должно описывать итерацию вложенных
коллекций, составную идентичность узла, путь к исходной записи формы и несколько
визуальных связей для одной записи. До этого адаптер сохраняет структуру чарта
без преобразования xroutes в искусственные плоские records.
